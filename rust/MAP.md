# Migration status

This table tracks the Rust implementation separately from compatibility code
that must remain available to existing Kotlin Multiplatform consumers.

| Area | Current implementation | Rust target | State / required gate |
| --- | --- | --- | --- |
| Symbol names, categories, restricted flags, aliases | KMP catalog and JVM tag file; Rust reads those same sources at compile time | `sfstudio-core` | `PORTED`; catalog count and basic lookup tests pass; Rust builds on Windows/macOS/Linux |
| Fuzzy query ranking | Kotlin search remains the fallback and reference | `sfstudio-core` via C ABI | `VERIFIED`; 37-query JNA parity passed on Windows/macOS/Linux in Actions run #14 |
| Category and favorites filtering | `CatalogViewModel.kt` retains a Kotlin fallback | `sfstudio-core::Catalog::search_filtered` via C ABI | `VERIFIED`; exact Kotlin/Rust parity and cross-OS JNA tests pass for category, favorites, blank, typo, and Unicode queries in run #17 |
| Cross-language core entry point | Rust core had no stable foreign-language ABI | `sfstudio-ffi` C ABI + `include/sfstudio.h` | `IN_PROGRESS`; search, filtering, filter-selection transitions, codegen, favorites, metadata, glyph geometry and point interpolation, Apple animation frames, layer appearance, draw-field levels, and MCP config generation are exposed; JVM and Android consume Rust outline points; Android effect, appearance, and draw-field JNI adapters are implemented with Kotlin fallbacks; Android main/device-test compilation and four-ABI packaging pass in run #44849774443, while device runtime parity remains pending; iOS, JS, and Wasm Rust adapters remain pending |
| Symbol metadata lookup | Kotlin catalog lookup is the reference | `sfstudio-core::Catalog::find` via `sfstudio_symbol_json` C ABI | `VERIFIED`; Rust and Python C ABI smoke and JVM parity passed Windows/macOS/Linux in run #20 |
| Vector data, geometry, and visible bounds | Generated Kotlin blobs are authoritative | `sfstudio-core::vector` | `IN_PROGRESS`; exact fingerprints match all 8,526 glyphs and available optical variants; visible bounds match Kotlin across ten symbols, all nine weights, and all three scales; JVM and Android use Rust-interpolated points with exact Kotlin parity on ten symbols, all nine weights, and all three scales |
| Desktop search caller | `FuzzySearch.kt` and `CatalogViewModel.kt` retain fallbacks | Rust search and filtered search via JNA C ABI | `VERIFIED`; search and filtering passed Windows/macOS/Linux in runs #14/#17 |
| JVM metadata lookup binding | Kotlin catalog lookup is the reference | Rust metadata lookup via JNA C ABI | `VERIFIED`; `CatalogViewModel.selectSymbol` uses Rust metadata for the detail selection and falls back to its supplied KMP metadata; endpoint parity passed Windows/macOS/Linux in run #20 and the live selection path passed Windows/macOS/Linux JVM checks in run #44 |
| MCP server | Kotlin `McpServer.kt` remains the development fallback | `sfstudio-mcp`; packaged `--mcp` launcher delegates to it | `VERIFIED`; 99 Kotlin/Rust response cases match locally; packaged smoke passes on Windows, macOS, and Linux |
| Favorites model and JSON codec | `PinnedSymbols.kt` remains the active disk reader/writer at `~/.sf-symbols-catalog/pins.json` | `sfstudio-core::favorites` via C ABI | `VERIFIED`; desktop toggle parity passed Windows/macOS/Linux in run #16; Kotlin still owns persistence |
| Compose snippet generation | Kotlin implementation remains the fallback and reference | `sfstudio-core::codegen` via C ABI | `VERIFIED`; Rust matches both golden fixtures and JNA parity passed Windows/macOS/Linux in run #16 |
| UI state and filtering | `CatalogViewModel.kt` | Rust search/filter core plus portable state transitions | `IN_PROGRESS`; query ranking, category/favorites search, and category/favorites/all selection transitions use Rust on desktop with Kotlin fallbacks; Compose navigation, selection, mode, colors, and grid/list state remain Kotlin |
| MCP client configuration | Kotlin `mcpClientConfig` used by the Settings screen | `sfstudio_core::mcp_config` through the C ABI | `VERIFIED`; desktop Settings calls Rust through JNA when available, with byte-exact parity for installed and development paths and Kotlin fallback; cross-OS checks passed in run #33 |
| Desktop UI | Kotlin/Compose | Rust-native UI if parity gates pass | `RETAINED_FOR_COMPATIBILITY`; visual and interaction baselines required |
| Vector rendering and symbol effects | KMP generated sources and Compose renderer | Rust geometry decoder, weight interpolation, effect evaluator, layer appearance, and draw-field levels; Compose retains path rasterization and clip construction | `IN_PROGRESS`; geometry, layers, bounds, weight interpolation, Apple effect timing, transforms, variable staging, replace recipes, Magic Replace path morphs, layer appearance, automatic gradients, and 48-step draw-field levels are in Rust. JVM `SfSymbolIcon` consumes Rust outline points, animation frames, sRGB appearance, gradients, and Draw On/Off reveal levels; Android consumes outline points plus new effect-frame, sRGB appearance, and draw-field JNI adapters with Kotlin fallbacks. Exact Kotlin point parity passes on JVM and Android; Android parity for the new adapters is pending device execution. iOS, JS, and Wasm retain Kotlin fallback; Rust path rasterization and clip construction remain pending |
| Published KMP API | `com.composables.sfsymbols` Kotlin API | Rust-backed adapters by target where feasible | `RETAINED_FOR_COMPATIBILITY`; Android/JVM/iOS/JS/Wasm remain unchanged |
| Installers and release identities | Compose Desktop packaging | Rust desktop packaging after upgrade proof | `RETAINED_FOR_COMPATIBILITY`; Windows UUID, macOS bundle ID and Debian package ID unchanged |
| Cross-platform verification | Existing Gradle targets and Rust workspace | Rust desktop matrix plus existing KMP jobs | JVM draw-field and outline-point integration are verified on Windows/macOS/Linux. Android JNI point parity and all four ABI libraries pass local packaging; a device parity test passes on Android 16 / API 36.1 x86_64. Run #44849774443 compiles Android main and device-test sources and packages all four ABIs; the new rendering device checks remain unexecuted because this Windows host has no Android SDK. iOS, JS, and Wasm Rust adapters remain pending |
| Desktop GUI cutover | Kotlin/Compose desktop app | Rust-native desktop app | `NOT_STARTED`; UI, vector, and interaction parity gates required |

The Rust MCP binary is bundled into standalone MCP assemblies and desktop
installers. Packaged `--mcp` invocations delegate to it; classpath-based Gradle
launches keep the Kotlin implementation as a development fallback.
