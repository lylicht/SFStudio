# Migration status

This table tracks the Rust implementation separately from compatibility code
that must remain available to existing Kotlin Multiplatform consumers.

| Area | Current implementation | Rust target | State / required gate |
| --- | --- | --- | --- |
| Symbol names, categories, restricted flags, aliases | KMP catalog and JVM tag file; Rust reads those same sources at compile time | `sfstudio-core` | `PORTED`; catalog count and basic lookup tests pass; Rust builds on Windows/macOS/Linux |
| Fuzzy query ranking | Kotlin search remains the fallback and reference | `sfstudio-core` via C ABI | `VERIFIED`; 37-query JNA parity passed on Windows/macOS/Linux in Actions run #14 |
| Category and favorites filtering | `CatalogViewModel.kt` retains a Kotlin fallback | `sfstudio-core::Catalog::search_filtered` via C ABI | `VERIFIED`; exact Kotlin/Rust parity and cross-OS JNA tests pass for category, favorites, blank, typo, and Unicode queries in run #17 |
| Cross-language core entry point | Rust core had no stable foreign-language ABI | `sfstudio-ffi` C ABI + `include/sfstudio.h` | `IN_PROGRESS`; search, filtering, filter-selection transitions, codegen, favorites, metadata, complete glyph/layer JSON, glyph geometry, point interpolation and visible bounds, Apple animation frames, layer appearance, draw-field levels and horizontal clip spans, and MCP config generation are exposed; Android four-ABI packaging and iOS device/simulator cinterop passed in run #44876469889; JS/Wasm sources compile, while browser runtime remains unverified |
| Symbol metadata lookup | Kotlin catalog lookup is the reference | `sfstudio-core::Catalog::find` via `sfstudio_symbol_json` C ABI | `VERIFIED`; Rust and Python C ABI smoke and JVM parity passed Windows/macOS/Linux in run #20 |
| Vector data, geometry, and visible bounds | Generated Kotlin blobs and layer flattening remain compatibility fallbacks | `sfstudio-core::vector` and `sfstudio-core::animation` through `sfstudio_glyph_json`, `sfstudio_glyph_points`, and `sfstudio_glyph_bounds` | `IN_PROGRESS`; Rust glyph JSON now includes flattened animation layers, which back the existing public `SfSymbol.layers` property when available. Full glyph/layer-tree fingerprints cover all 8,526 KMP symbols; every flattened layer field matches Kotlin on JVM. Weighted points and visible bounds use Rust through JVM, Android, and iOS adapters; Wasm runtime parity remains unverified because Node cannot load Skiko's `skiko.wasm`. Kotlin glyph decoding and layer flattening remain fallbacks. |
| Desktop search caller | `FuzzySearch.kt` and `CatalogViewModel.kt` retain fallbacks | Rust search and filtered search via JNA C ABI | `VERIFIED`; search and filtering passed Windows/macOS/Linux in runs #14/#17 |
| JVM metadata lookup binding | Kotlin catalog lookup is the reference | Rust metadata lookup via JNA C ABI | `VERIFIED`; `CatalogViewModel.selectSymbol` uses Rust metadata for the detail selection and falls back to its supplied KMP metadata; endpoint parity passed Windows/macOS/Linux in run #20 and the live selection path passed Windows/macOS/Linux JVM checks in run #44 |
| MCP server | Kotlin `McpServer.kt` remains the development fallback | `sfstudio-mcp`; packaged `--mcp` launcher delegates to it | `VERIFIED`; 99 Kotlin/Rust response cases match locally; packaged smoke passes on Windows, macOS, and Linux |
| Favorites model and JSON codec | `PinnedSymbols.kt` resolves `~/.sf-symbols-catalog/pins.json` and keeps the storage fallback | `sfstudio-core::favorites` via C ABI; Rust FFI loads and writes desktop favorites files through same-directory temporary replacement | `VERIFIED`; Rust preserves the ordered JSON array, path, and existing permissions; Rust C ABI and JVM parity pass on Windows/macOS/Linux in run #44869413797 |
| Compose snippet generation | Kotlin implementation remains the fallback and reference | `sfstudio-core::codegen` via C ABI | `VERIFIED`; Rust matches both golden fixtures and JNA parity passed Windows/macOS/Linux in run #16 |
| UI state and filtering | `CatalogViewModel.kt` | Rust search/filter core plus portable state transitions and preference rules | `IN_PROGRESS`; query ranking, category/favorites search, category/favorites/all selection transitions, System/Light/Dark resolution, and grid-scale clamping use Rust on desktop with Kotlin fallbacks; Compose navigation, persistence, selection, mode, colors, and grid/list state remain Kotlin |
| MCP client configuration | Kotlin `mcpClientConfig` used by the Settings screen | `sfstudio_core::mcp_config` through the C ABI | `VERIFIED`; desktop Settings calls Rust through JNA when available, with byte-exact parity for installed and development paths and Kotlin fallback; cross-OS checks passed in run #33 |
| Desktop UI | Kotlin/Compose | Rust-native UI if parity gates pass | `RETAINED_FOR_COMPATIBILITY`; an in-session Windows layout observation is recorded in [UI_BASELINE.md](UI_BASELINE.md), while saved screenshots, minimum-size/theme/accessibility comparisons, and a Rust UI probe remain gated |
| Vector rendering and symbol effects | KMP generated sources and Compose renderer | Rust glyph decoder, layer flattening, weight interpolation, effect evaluator, layer appearance, draw-field levels and horizontal clip spans; Compose retains platform rasterization and `Path` materialization | `IN_PROGRESS`; glyph masters, flattened animation layers, bounds, weight interpolation, Apple effect timing, transforms, variable staging, replace recipes, Magic Replace path morphs, layer appearance, gradients, and 48-step draw-field spans are implemented in Rust. The existing KMP `SfSymbol.layers` property consumes Rust flattened layer metadata when available and retains Kotlin fallback. JVM parity compares every flattened layer field for all 8,526 symbols; draw spans reconstruct Kotlin's stored raster fixtures. Run #44885280359 passed the JVM, Android compile/packaging, iOS simulator, JS Node, and Wasm compilation gates. Android rendering runtime, iOS physical-device runtime, and Wasm browser runtime remain unverified. Platform rasterization and path materialization stay in Compose for antialiasing and compatibility |
| Published KMP API | `com.composables.sfsymbols` Kotlin API | Rust-backed adapters by target where feasible | `RETAINED_FOR_COMPATIBILITY`; Android/JVM/iOS/JS/Wasm remain unchanged |
| Installers and release identities | Compose Desktop packaging | Rust desktop packaging after upgrade proof | `RETAINED_FOR_COMPATIBILITY`; Windows UUID, macOS bundle ID and Debian package ID unchanged |
| Cross-platform verification | Existing Gradle targets and Rust workspace | Rust desktop matrix plus existing KMP jobs | JVM app/library suites passed on Windows/macOS/Linux, Rust checks passed on all three OSes, Android compile/four-ABI packaging, iOS device/simulator compilation/tests, JS Node parity, Wasm compilation, packaged MCP launchers, and differential replay passed in run #44885280359. Exhaustive glyph/layer-tree parity passes locally on JVM; Wasm runtime remains unverified due Compose Skiko and Karma resource-serving issues. Android rendering runtime and iOS physical-device runtime remain unverified |
| Desktop GUI cutover | Kotlin/Compose desktop app | Rust-native desktop app | `NOT_STARTED`; UI, vector, and interaction parity gates required |

The Rust MCP binary is bundled into standalone MCP assemblies and desktop
installers. Packaged `--mcp` invocations delegate to it; classpath-based Gradle
launches keep the Kotlin implementation as a development fallback.
